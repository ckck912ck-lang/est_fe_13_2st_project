# QA 체크리스트

구현 완료 후 PR을 올리기 전에 아래 항목을 확인합니다.

## 1. 기본 확인

- [ ] 모바일 360px 화면에서 레이아웃이 깨지지 않는다.
- [ ] 콘솔 에러가 없다.
- [ ] 이미지에 `alt` 속성이 있다.
- [ ] 버튼과 링크에 접근 가능한 이름이 있다.
- [ ] 버튼 hover/focus 상태를 확인했다.
- [ ] HTML에는 `css/style.css` 하나만 연결되어 있다.
- [ ] `css/style.css`를 직접 수정하지 않았다.
- [ ] 공통 기능 수정 시 팀원에게 공유했다.

## 2. 기능 테스트

- [ ] 핵심 워크플로우가 정상 동작한다.
- [ ] 데이터 조회, 렌더링, 저장이 정상 동작한다.
- [ ] 필수값 미입력 시 적절히 처리된다.
- [ ] 이메일, 비밀번호 등 폼 입력 형식을 확인했다.
- [ ] 링크와 버튼이 올바른 페이지 또는 기능으로 연결된다.
- [ ] 404 또는 빈 페이지로 이동하는 링크가 없다.

## 3. UI/UX 및 반응형

- [ ] 모바일, 태블릿, PC 화면을 확인했다.
- [ ] 가로/세로 방향 전환 시 레이아웃이 무너지지 않는다.
- [ ] 폰트 크기, 간격, 컬러가 디자인 시안과 크게 어긋나지 않는다.
- [ ] 이미지 비율이 깨지지 않는다.
- [ ] 인터랙션이 의도대로 동작한다.

## 4. 접근성

- [ ] `html` 태그에 `lang="ko"`가 있다.
- [ ] 이미지에 의미 있는 `alt`를 작성했다.
- [ ] 장식용 이미지는 빈 `alt` 또는 `aria-hidden="true"`를 사용했다.
- [ ] 폼 요소에 `label`을 연결했다.
- [ ] 색상만으로 상태를 구분하지 않는다.
- [ ] 키보드로 주요 버튼과 링크에 접근할 수 있다.
- [ ] focus 스타일이 보인다.

## 5. 성능 및 로딩

- [ ] 이미지 용량이 과도하게 크지 않다.
- [ ] 필요 없는 CSS/JS를 추가하지 않았다.
- [ ] 데이터 로딩 실패 시 에러 UI 또는 안내가 있다.
- [ ] 네트워크 지연 시 로딩 UI 또는 스켈레톤 UI를 고려했다.
- [ ] Lighthouse 성능 저하 요인을 확인했다.

## 6. 장바구니/localStorage

- [ ] 장바구니 담기가 정상 동작한다.
- [ ] localStorage 저장값이 정상 반영된다.
- [ ] 새로고침 후에도 상태가 유지된다.
- [ ] 수량 변경이 정상 동작한다.
- [ ] 삭제 버튼이 정상 동작한다.
- [ ] 총 금액 계산이 정상 동작한다.

## 7. 크로스 브라우징

- [ ] Chrome에서 확인했다.
- [ ] Edge에서 확인했다.
- [ ] 가능하면 Safari 또는 Firefox에서 확인했다.
- [ ] 브라우저별 레이아웃 차이가 큰 부분을 확인했다.

## 8. PR 전 최종 확인

- [ ] 작업 브랜치 이름이 컨벤션에 맞다.
- [ ] 커밋 메시지에 작업 내용이 드러난다.
- [ ] PR 설명에 수정 파일과 구현 내용을 적었다.
- [ ] PR 크기가 지나치게 크지 않다.
- [ ] 충돌 여부를 확인했다.
